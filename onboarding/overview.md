# rh-proof-skeleton — Overview

## What This Repo Is

The repository houses the deterministic Lean proof-skeleton pipeline, including its Phase 0 upstream audit emitter and read-only upstream freshness triage CLI (`rh-check-upstream`), its Phase 1 closed-world Lean 4 declaration extractor and 8-stage skeleton/DAG generator, its deterministic schema, Concept Card, Lean-anchor and Level-1 jargon validation suite, and its Phase 4 static VitePress site compiler and editorial theme shell. The worktree quality checks and CI site-build check verify this checkout before its changes are handed on.

## Code Ownership

The repository layout assigns each package one responsibility. Neutral top-level [markdown masking primitives](src/rh_pipeline/markdown_mask.py.md) sit below both `validate` and `site` with zero domain dependencies. `validate` owns deterministic gates: the [file-size rail](src/rh_pipeline/validate/file_size.py.md), [artifact schema validator](src/rh_pipeline/validate/schemas.py.md), [Concept Card corpus validator](src/rh_pipeline/validate/concepts.py.md) and [explainer directive and Level-1 jargon validator](src/rh_pipeline/validate/jargon.py.md). `models` owns immutable data contracts, pure parsers and canonical JSON formatting, including the [Phase 0 audit models](src/rh_pipeline/models/audit.py.md), [Phase 1 Lean models](src/rh_pipeline/models/lean.py.md), [stage-map and DAG models](src/rh_pipeline/models/dag.py.md), [validation-finding models](src/rh_pipeline/models/validation.py.md) and [pure Concept Card models, YAML parser and shared plain-text LaTeX/variant helpers](src/rh_pipeline/models/concepts.py.md); `audit` owns read-only [provenance collection](src/rh_pipeline/audit/provenance.py.md), [Lean lexical static scanning](src/rh_pipeline/audit/static_scan.py.md), [verification-status assembly and atomic emission](src/rh_pipeline/audit/status.py.md) and [upstream freshness triage](src/rh_pipeline/audit/triage.py.md); `lean` owns [the Lean 4 lexer](src/rh_pipeline/lean/_lexer.py.md), the [closed-world Lean 4 parser](src/rh_pipeline/lean/parser.py.md) and [deterministic stub emitter](src/rh_pipeline/lean/stub_emitter.py.md); `graph` owns [nearest-landmark import projection](src/rh_pipeline/graph/import_projection.py.md) and [stage-map validation, DAG assembly and atomic extraction](src/rh_pipeline/graph/stage_map.py.md); `site` owns Phase 4 deterministic static-site compilation across [its package facade](src/rh_pipeline/site/__init__.py.md), [Markdown transforms](src/rh_pipeline/site/markdown_transforms.py.md), [page and minimap renderers](src/rh_pipeline/site/renderers.py.md) and [atomic site compiler](src/rh_pipeline/site/compiler.py.md); and `cli` owns thin command wiring, including [`rh-audit`](src/rh_pipeline/cli/audit.py.md), [`rh-build-site`](src/rh_pipeline/cli/build_site.py.md), [`rh-check-upstream`](src/rh_pipeline/cli/check_upstream.py.md), [`rh-extract`](src/rh_pipeline/cli/extract.py.md) and [`rh-validate`](src/rh_pipeline/cli/validate.py.md). Under `audit/`, [the audit README](audit/README.md.md) documents [provenance.json](audit/provenance.json.md) and [verification-status.json](audit/verification-status.json.md). Under `site/`, [the VitePress package](site/package.json.md), [lockfile](site/package-lock.json.md), [configuration](site/docs/.vitepress/config.mts.md), [theme entry](site/docs/.vitepress/theme/index.ts.md), [editorial light tokens](site/docs/.vitepress/theme/tokens.css.md) and four Vue components ([`VerificationBanner`](site/docs/.vitepress/theme/components/VerificationBanner.vue.md), [`ConceptReveal`](site/docs/.vitepress/theme/components/ConceptReveal.vue.md), [`ConceptHover`](site/docs/.vitepress/theme/components/ConceptHover.vue.md) and [`ZoomTabs`](site/docs/.vitepress/theme/components/ZoomTabs.vue.md)) render build-time MathJax 3 SVG math and script-off-readable pages from compiled outputs ignored by [`.gitignore`](.gitignore.md). See the [README card](README.md.md) for the package map.

## Build and Development

Run [bootstrap](scripts/bootstrap-venv.sh.md) and then the [quality runner](scripts/check-quality.sh.md) from the worktree root. [GitHub Actions](.github/workflows/quality.yml.md) runs those same Python scripts in `python-gates` and verifies static site compilation plus `npm ci && npm run docs:build` against a synthetic fixture in `site-build-check`; public GitHub Pages deployment is owned by `ar-rh-proof-skeleton/.github/workflows/pages.yml`. The file-size rail classifies Python files into five bands, reports non-healthy files and fails when a default scan finds a file above 1200 lines. [Package metadata](pyproject.toml.md) registers `rh-audit`, `rh-build-site`, `rh-check-upstream`, `rh-extract`, `rh-file-size-gate` and `rh-validate` as console scripts; running `rh-audit` against read-only upstream checkouts regenerates deterministic, timestamp-free [provenance](audit/provenance.json.md) and [verification status](audit/verification-status.json.md) snapshots, running `rh-check-upstream` performs read-only freshness triage against pinned provenance and the stage map with deterministic exit codes (`0`, `10`, `11`, `2`), running `rh-extract` with [the 8-stage map](dag/stage-map.json.md) regenerates deterministic 8-stage `skeleton/*/*.lean` stubs and [the 8-stage proof DAG](dag/dag.json.md), running `rh-validate` checks repository JSON schemas plus optional Concept Card, Lean-anchor and Level-1 jargon gates under `<memory>/docs/{concepts,stages}/` (never scanning AR `onboarding/`), running inside `scripts/check-quality.sh` before `pytest`, and running `rh-build-site` compiles the external memory repository's dependent stage explainer essays (`docs/stages/*/*.md`, requiring `docs/stages/00_statement/overview.md`), Concept Cards (`docs/concepts/*.md`) and SVG assets (`docs/assets/*.svg`)—which stand on `skeleton/*/*.lean`, `dag/dag.json` and `audit/verification-status.json`—atomically into `site/docs/` without touching `.vitepress/`.

- The rh-audit CLI runs provenance collection, static scanning, status assembly and atomic artifact emission. [4]
- The rh-extract CLI orchestrates stage-map validation, closed-world Lean extraction, stub rendering, nearest-landmark projected DAG construction and atomic emission. [5]
- The rh-validate CLI composes repository schema validation with optional Concept Card, Lean-anchor and Level-1 jargon checks under docs/. [6]
- The rh-build-site CLI compiles validated stage explainers, Concept Cards, SVG assets, audit status and DAG data atomically into VitePress docs. [7]
- The rh-check-upstream CLI runs read-only upstream freshness triage against pinned provenance and the stage map, returning deterministic classification exit codes. [8]
